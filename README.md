# الصرح التعليمي | ALSARH EDUCATIONAL SYSTEM

**المنظومة المتكاملة للتعليم والإدارة والحسابات** · الإصدار التأسيسي `0.2.0`.

المستودع يحتوي على **نسخة ويب وخادم Node.js + SQLite**، و**تطبيق Android**، و**برنامج Windows Electron** من واجهة مشتركة. الهوية عربية RTL، كحلي/ذهبي، واجهة بطاقات و3 أيقونات في الصف على الهاتف.

## ابدأ بالتجربة على الهاتف مباشرة (دون Hostinger)

1. افتح GitHub Actions → `Build Android APK` → آخر تشغيل ناجح → قسم `Artifacts` → نزّل `alsarh-android-apk` ثم استخرج `app-debug.apk` وثبته. التطبيق التجريبي غير موقّع بتوقيع نشر تجاري.
2. افتح التطبيق. **لا يطلب رابط HTTPS**: شاشة إعداد المؤسسة تعمل **محليًا** وتسمح بإنشاء مدير وكلمة مرور. لا تستخدم بيانات طلاب حقيقيين قبل تدقيق الحماية.
3. من **الإعدادات** يمكن إضافة بيانات تجريبية *إلى مؤسسة فارغة فقط* لتجربة القوائم والترابط؛ لن تُضاف تلقائيًا.
4. من الإعدادات → **تصدير نسخة JSON**؛ احفظ الملف قبل حذف التطبيق أو تنظيف بياناته. الحفظ المحلي على الهاتف باستخدام IndexedDB ويمكن فقده عند حذف التطبيق.

نسخة Windows تبدأ بدورها في الوضع المحلي بدون خادم، مع خيار الاتصال لاحقًا برابط HTTPS. عند نقل التطبيق من المحلي للخادم تصبح البيانات **منفصلة** حتى يتم استيراد ملف التصدير في خادم جديد.

## الأقسام المتاحة ونوع العمل

| المجال | الأقسام |
|---|---|
| الإدارة | المدرسة والمستخدمون والصلاحيات، الصفوف والشعب، المعلمون والموظفون، أولياء الأمور، النقل والتعاميم والاجتماعات |
| التعليم | الطلاب، المواد، الخطط والمناهج، الدروس، الكتب، المراجعات، بنك الأسئلة، الواجبات وتسليماتها، الاختبارات والدرجات، الجدول والحضور، السلوك وإعارة الكتب |
| الحسابات | رسوم الطلاب وإصدار الأقساط، تحصيل نقدي أو بنكي، مصروفات، سند قبض، ميزان مراجعة بقيود مزدوجة |
| إضافات | جرد أولي، خطط الرواتب **كتسجيل إداري فقط** دون ترحيل أو صرف رواتب، تقارير ولوحة مؤشرات وطباعة |

العلاقات الموجودة حاليًا: طالب→صف→مادة→درس/واجب/اختبار، الاختبار→الدرجة، الواجب→التسليم، طالب→قسط→تحصيل، القيد→الحسابات، المستخدم→الصلاحية. توجد قيود تمنع تجاوز الدرجة النهائية وتكرار حضور الطالب في نفس اليوم وتجاوز الرصيد المستحق؛ وتفصل صلاحيات المعلمين وأولياء الأمور والطلاب.

**حدود واضحة:** هذا إصدار تطوير/تجربة وليس نظامًا إنتاجيًا معتمدًا. بنك الأسئلة وملفات المناهج حقول مدخلة يدويًا، ولا يوجد محرر اختبارات تفاعلية تلقائي أو رفع ملفات PDF داخل التطبيق، ولا دفع بنكي أو رسائل جماعية أو احتساب رواتب تلقائي أو مساعد AI. لا توجد مزامنة حية بين وضع الهاتف المحلي والخادم؛ النقل يتم بالنسخة الاحتياطية بعد اكتمال اختبارها. وضع الهاتف المحلي يصلح للتجربة والبيانات غير الحساسة؛ تشغيل عدة مدارس وإدارة فروع متعددة تحتاج أعمالًا إضافية.

## تشغيل نسخة الويب والخادم محليًا

يتطلب **Node.js 22.16.x** (SQLite المدمجة مع `--experimental-sqlite`). الخادم لا يحتاج `npm install`.

```bash
npm start
# افتح http://localhost:8787
npm run check
npm test
```

للعمل بوضع مستقل ومحلي داخل المتصفح مع الاحتفاظ بالبيانات في IndexedDB للمتصفح:

`http://localhost:8787/?offline=1`

قاعدة بيانات الخادم في `data/alsarh.sqlite`. لا ترفع `data/` إلى GitHub.

## نقل المنظومة لاحقًا إلى Hostinger VPS

**المتطلبات:** Hostinger VPS مع Docker وDocker Compose، ودومين موجّه إلى عنوانه، والمنفذان 80/443 متاحان. الاستضافة المشتركة العادية لا تكفي لخادم Node+SQLite بهذا النمط.

1. حمّل مستودع المشروع بالكامل، وانقل الملفات إلى VPS.
2. وجّه DNS سجل A لاسم النطاق الذي تختاره، ثم داخل مجلد `deploy` انسخ `.env.example` إلى `.env` واكتب `ALSARH_DOMAIN=school.yourdomain.com`.
3. شغّل `docker compose up -d --build` من مجلد `deploy`. ‏Caddy يوفر HTTPS بعد وصول الدومين إلى VPS.
4. افتح الموقع عبر `https://school.yourdomain.com` وأنشئ **مؤسسة جديدة فارغة وحساب مدير جديد**.
5. من الواجهة بعد تسجيل الدخول مديرًا → الإعدادات → **استيراد نسخة الجهاز** → اختر ملف JSON المصدَّر من النسخة المحلية. يتم النقل داخل معاملة SQLite واحدة مع فحوصات للأرصدة والروابط. يجب أن تكون المؤسسة على الخادم **فارغة** تمامًا، والمستخدم الوحيد فيها هو المدير الأول.
6. حسابات المعلمين والطلاب وأولياء الأمور تُنقل دون كلمات مرور صالحة للدخول. من قائمة المستخدمين يعيّن المدير كلمة مرور جديدة لكل حساب، ثم يبلّغ صاحب الحساب بطريقة آمنة.
7. من إعدادات تطبيق Android/Windows أدخل رابط الخادم HTTPS للانتقال إليه. يبقى وضع التجربة المحلي منفصلًا ويمكن الرجوع إليه؛ لا يحدث دمج تلقائي.

**قبل التشغيل الحقيقي** نفّذ اختبارات صلاحيات وأمان وخصوصية مستقلة، واحفظ نسخًا احتياطية مشفرة خارج VPS مع تجربة استعادتها، واضبط آليات مراقبة الأداء والتحديثات ودليل المستخدمين. لا تستخدم حساب مدير واحدًا للجميع.

## مكونات الكود

```text
web/                 الواجهة المشتركة + offline.js (IndexedDB) + PWA
server/index.js      REST API وSQLite وحماية الجلسات وإدارة الحسابات وترحيل النسخ
android/             Native Android WebView + WebViewAssetLoader + مشاركة نسخ JSON
 desktop/            Windows Electron مع بروتوكول محلي آمن وملفات ويب مدمجة
 tests/              اختبارات API، دورة محاسبة، وضع محلي، وترحيل بيانات
 deploy/             Docker + Caddy HTTPS
 .github/workflows/    بناء APK وWindows واختبارات CI
```

## ملحوظات البيانات والأمان

- النسخة المحلية تحفظ البيانات على **الجهاز نفسه** في مساحة تطبيق Android أو مساحة مستخدم Electron. حذف التطبيق أو مسح بياناته قد يؤدي إلى فقدها.
- ملف JSON غير مشفر افتراضيًا ويحتوي على سجلات مدرسية و**تجزئات** كلمات مرور الجهاز المحلي. لا ترسله إلى أي طرف آخر ولا ترفعه علنًا.
- لا يوجد مفتاح API سري ولا بيانات مستخدمين ضمن ملفات المستودع، وجميع الملفات التي تُرفع إلى GitHub ملفات كود/تجهيزات دون حسابات حقيقية.
- حزم APK الاختبارية Debug وليست للنشر على متجر Google Play. يلزم توقيع إصدار Release وفحص سلامة التطبيق قبل التوزيع.
